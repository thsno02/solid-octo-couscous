\begin{abstract}
    While large pre-trained models have enabled impressive results on a variety of downstream tasks, the largest existing models still make errors, and even accurate predictions may become outdated over time. Because detecting all such failures at training time is impossible, enabling both developers and end users of such models to correct inaccurate outputs while leaving the model otherwise intact is desirable. However, the distributed, black-box nature of the representations learned by large neural networks makes such targeted edits difficult to apply. If presented with only a single problematic input and new desired output, fine-tuning approaches are slow and tend to overfit. Other existing editing algorithms are either computationally infeasible or simply ineffective when applied to very large models. To enable easy post-hoc editing at scale, we propose \name, a collection of small auxiliary editing networks that learn to use a single desired input-output pair to make fast, local edits to a pre-trained model. \name~transforms the gradient obtained by standard fine-tuning, using a low-rank decomposition of the gradient to make the parameterization of this transformation tractable. \name~can be trained on a single GPU in less than a day even for 10 billion+ parameter models; once trained \name~enables near-instantaneous editing of an existing model. Our experiments with the T5, GPT, BERT, and BART model classes show that \name~is the only approach to model editing that produces effective edits for models with tens of million to over 10 billion parameters.
\end{abstract}

\section{Introduction}
\label{sec:intro}

\input{figures_tex/fig1}

Large neural networks have become a fundamental tool in solving data-driven problems in computer vision \citep{huang2017densely}, natural language and audio processing \citep{vaswani2017attention}, and sequential decision making \citep{wu2021greedy}. However, deploying and maintaining such models can be difficult: when a neural network produces an undesirable output, making a localized update to correct its behavior for a single input or small number of inputs is non-trivial, owing to the distributed nature of the model's representation. The computational requirements of large scale state-of-the-art language models exacerbates this challenge. For example (see Figure~\ref{fig:problem-method}), after being trained on data gathered from the internet, a large language model might assign higher probability to \textit{Theresa May} than to \textit{Boris Johnson} when presented with \textit{Who is the prime minister of the UK?} as a prompt (for an example with a real T5 model \citep{2020t5} see Table~\ref{tab:examples}). An ideal model editing procedure could quickly update the model parameters to increase the relative likelihood of \textit{Boris Johnson} without changing the model output for unrelated inputs. This procedure would produce edits that exhibit \textit{reliability}, successfully changing the model's output on the problematic input; \textit{locality}, minimally affecting the model's output for unrelated inputs; and \textit{generality}, also generating the corrected output for inputs that are related to the edit input (e.g., \textit{Who is the UK PM?}).

A simple approach to making such edits is additional fine-tuning with a new label for the example that needs to be corrected. Yet fine-tuning on just the problematic input with a new label tends to overfit to that example, even when constraining the distance between the pre- and post-fine-tuning parameters \citep{zhu2020modifying,Cao2021EditingFK}; we corroborate this finding in our experiments in Sections~\ref{sec:large-models} and~\ref{sec:small-scale}. This overfitting leads to failures of both locality and generality, and while fine-tuning on the edit example in conjunction with continued training on the training set better enforces locality, it does not provide generality. Further, it requires persistent access to the full training set during test time and is more computationally demanding. As an alternative to fine-tuning, recent work has considered the problem of learning to edit. \cite{Sinitsin2020Editable} describe a bi-level meta-learning objective that finds a model initialization for which regular, unconstrained fine-tuning on a single edit example and label produces quick, local edits. While this strategy is effective, its computational requirements also make scaling to very large models difficult, where fast, effective edits are most needed. A computationally efficient alternative to learning to edit \citep{Cao2021EditingFK} fails to produce useful edits for very large models in our experiments. We thus devise an approach to model editing that yields reliable, local, and general edits, while being easy to scale to extremely large (over 10 billion parameter) models.

Our approach uses lightweight \textit{model editor networks} that can produce edits to a pre-trained model's weights when provided with the standard fine-tuning gradient of a given correction as input. Because gradients are high-dimensional objects, directly parameterizing a function that maps a gradient into a modified update is enormously costly. Even for a single $d \times d$ weight matrix, a naive implementation of this gradient mapping function requires a mapping from $\mathbb{R}^{\mathcal{O}(d^2)} \rightarrow \mathbb{R}^{\mathcal{O}(d^2)}$, which is impractical for large models where $d\sim10^4$. However, by \textit{decomposing} this gradient into its rank-1 outer product form, our approach is instead able to learn a function $g:\mathbb{R}^{\mathcal{O}(d)} \rightarrow \mathbb{R}^{\mathcal{O}(d)}$. We call our approach \fullname~(\name). \name~parameterizes these gradient mapping functions as MLPs with a single hidden layer (Figure~\ref{fig:arch}), using a small number of parameters compared with large pre-trained models with tens of billions of parameters. \name~can be applied to any pre-trained model, regardless of pre-training.

The primary contribution of this work is an effective algorithm for fast model editing that scales to the largest publicly available pre-trained models by leveraging the low-rank structure of fine-tuning gradients. Our experiments utilize a variety of language-related tasks and transformer models, showing that \name~is the only algorithm that can consistently edit the largest GPT-2 \citep{radford2019language} and T5 \citep{2020t5} language models. Finally, our ablation experiments highlight the impact of \name's key design choices, showing that variants of \name~are likely to scale to models with hundreds of billions of parameters.


\section{The Model Editing Problem}
The goal of model editing is to use a single pair of input $\xe$ and desired output $\ye$ to alter a \textit{base model}'s output for $\xe$ as well as the \textit{equivalence neighborhood} (related input/output pairs) of $\xe$, while leaving model behavior on unrelated inputs unchanged. For a question-answering model, a \textit{model editor} would use a question and new desired answer to update the model in a way that correctly answers the question and its semantically-equivalent rephrasings without affecting model performance on unrelated questions. Some model editors (like ours) use a training phase before they can apply edits; this phase uses an edit dataset (separate from the dataset the original model was trained on) that specifies the types of model edits that will be made.

More precisely, the base model $\basemodel:\mathcal{X} \times \Theta \rightarrow \mathcal{Y}$ is a differentiable function mapping an input $x$ and set of parameters $\theta$ to an output $y$. A model editor is a function $E : \mathcal{X} \times \mathcal{Y} \times \Theta \times \mathcal{L} \times \Phi \rightarrow \Theta$ that maps an \textit{edit input} $\xe$, \textit{edit label} $\ye$, loss function $l:\mathcal{X} \times \mathcal{Y} \times \Theta \rightarrow \mathbb{R}$, set of model parameters $\theta$, and optional editor parameters $\phi$ to a new set of model parameters $\theta'_{\xe,\ye}$. In line with past work \citep{Sinitsin2020Editable,Cao2021EditingFK}, we use the loss function $l(x,y,\theta) = p_\theta(y|x)$, but other choices are possible. Model editors are evaluated with a held-out dataset $\dtest = \{(\xe,\ye,\xloc,\xe',\ye')_i\}$. The locality input $\xloc$ is unrelated to $\xe$ and is used to quantify the extent to which model predictions change for unrelated outputs. The alternative edit input and label $\xe'$ and $\ye'$ are sampled from the \textit{equivalence neighborhood} $\mathcal{N}(\xe,\ye)$ of $\xe$ and $\ye$, the set of inputs (and their corresponding new outputs) for which the model's output should be updated to reflect the new information in $\xe,\ye$.

We call a model editor reliable if $l(\xe,\ye,\theta'_{\xe,\ye})$ is small on average for $\dtest$. We call a model editor local if $\text{KL}(p_\theta(\cdot | \xloc) \| p_{\theta'_{\xe,\ye}}(\cdot | \xloc))$ is small on average for $\xloc$ sampled from $\dtest$. We say a model editor generalizes if $l(\xe',\ye',\theta'_{\xe,\ye})$ is small on average for $\dtest$. To fit the model editor parameters $\phi$, some algorithms (including the one we propose) utilize a dataset $\dtrain$ of edits, containing tuples similar to $\dtest$. We call a model editor efficient if the compute time and memory requirements for computing $\phi$ as well as the time and memory required to evaluate $E$ are small. We can thus define \textit{edit success} to summarize both reliability and generality; it is measured as the average accuracy of the edited model $p_{\theta'_{\xe,\ye}}$ on the edit input as well as inputs drawn from the equivalence neighborhood:
\begin{equation}
    \text{ES} = \frac{1}{|\mathcal{N}(\xe,\ye)|}\sum_{\xe',\ye' \in \mathcal{N}(\xe,\ye)}\mathbbm{1}\{\argmax_yp_{\theta'_{\xe,\ye}}(y|\xe') = \ye'\}.
    \label{eq:edit-success}
\end{equation}

\section{\fullname}
Broadly, \name~is a procedure that takes a pre-trained model $\basemodel$ and edit training set $\dtrain$ to produce a collection of model editor networks $g_\ell$ that each edit the model's layers given new edit example pairs $(\xe, \ye)$ at test time. Each editor function transforms the fine-tuning gradient for a particular layer into a parameter update for the layer that provides the reliability, locality, generality, and efficiency properties described earlier. Because gradients are high-dimensional objects, the input and output spaces of these networks are also very high-dimensional, and parameterizing them in a computationally feasible manner is challenging. In this section, we describe how \name~does so, starting with a low-rank factorization of fully-connected layer gradients. We then describe the initialization and normalization schemes needed to train this parameterization.

\subsection{A parameter-efficient transformation of high-dimensional gradients}

\input{figures_tex/arch}

Making more precise the high-level description above, the input to a \name~network $g_\ell$ is the fine-tuning gradient $\nabla_{W_\ell} p_\theta(\ye|\xe)$ for layer $\ell$ and the output is the parameter edit for layer $\ell$, which we call $\tilde\nabla_{W_\ell}$. As noted in Section~\ref{sec:intro}, for a $d \times d$ weight matrix, this function has $d^2$ inputs and $d^2$ outputs. Even if we restrict $g_\ell$ to be a linear network with no hidden layers and restrict $g_\ell$ to output a rank-1 parameter edit (motivated by the effectiveness of low-rank model edits observed by \cite{hu2021lora}), this function would still require $d^2(d+d) = 2d^3$ parameters. For a low-rank linear parameterization of $g_\ell$ with rank $r$, we have $r(d^2 + 2d)$ parameters, which still carries an unacceptable cost for non-trivial $r$, considering that $d\sim 10^4$ for some large models \citep{radford2019language,2020t5}.

We solve this problem using the fact that the input to $g_\ell$, the fine-tuning gradient, is itself a rank-1 matrix. That is, the gradient of some loss $L$ with respect to a weight matrix $W_{\ell}$ in layer $\ell$ of a neural network is a rank-1 matrix for each element in the batch $\nabla_{W_\ell}L = \sum_{i=1}^B\delta_{\ell + 1}^i{u_\ell^{i\,\top}}$, where $B$ is the batch size, $\delta_{\ell+1}$ is the gradient of the loss for batch element $i$ with respect to the \textit{preactivations} at layer $\ell+1$, and $u_\ell$ are the activations for batch element $i$ at layer $\ell$ (see Alg.~6.4 of \citealp{Goodfellow-et-al-2016} or Ch.~2 of \citealp{nielsen2015neural}). This formulation is easily extended to sequence models such as Transformers \citep{vaswani2017attention,radford2019language} with an additional sum over sequence index $j$; for simplicity, we merge this index with the batch index without loss of generality. This property enables a network to condition directly on the gradient with only $2d$ (rather than $d^2$) input neurons with no approximation error. With this parameterization, \name~learns functions $g_\ell$ with parameters $\phi_\ell$ mapping $u_\ell$ and $\delta_{\ell+1}$ to \textit{pseudoactivations} $\tilde u_\ell$ and \textit{pseudodelta} $\tilde\delta_{\ell+1}$. The model edit for weight matrix $W_\ell$ for a batch of $B$ edit examples is
\begin{align}
    \tilde{\nabla}_{W_\ell} &= \sum_{i=1}^B\tilde\delta_{\ell + 1}^{i}{\tilde u_\ell^{i\,\top}}
\end{align}
Finally, to further reduce the parameters used by \name, we share parameters across the editor networks $g_\ell$. Because the sizes of $u_\ell$ and $\delta_{\ell+1}$ depend on the shape of the weight matrix $W_\ell$, we learn a separate set of editor parameters for each unique \textit{shape} of weight matrix to be edited; if we edit all of the MLP layers in a transformer-based architecture, this sharing scheme entails learning only 2 sets of editor parameters (one for all of the first MLP layers, one for the second MLP layers). To enable some layer-wise specialization, \name~applies a layer-specific scale and shift (similar to FiLM layers \citep{perez2018film}) to the editor network hidden state and output.

To summarize, \name~parameterizes $g_\ell$ as an MLP with low-rank weight matrices, residual connections, and a single hidden layer; see Figure~\ref{fig:arch}. For each edit example in the batch, the inputs $u_\ell^i$ and $\delta_{\ell+1}^i$ are concatenated and passed together to $g_\ell$, which produces a vector of equal cardinality, which is then split into pseudoactivations $\tilde u_\ell^i$ and pseudodeltas $\tilde \delta_{\ell+1}^i$. In the next subsection, we describe the nuances of this architecture in greater detail. 

\subsection{Effective initialization and normalization for editor networks}
While the parameterization presented in the previous section can tractably \textit{represent} a mapping from gradients to model edits, optimizing it to provide useful edits presents its own challenges. Specifically, the random initialization typically used for MLPs sacrifices a useful prior that we would like to retain, and the scaling of the inputs to \name~networks makes input normalization important.

\input{algs/mend}

\textbf{Initialization} While random initialization is effective for neural networks in many settings, it sacrifices the prior that the raw fine-tuning gradient is a useful starting point for effective model edits. We find in our ablations that it also leads to less productive model edits. For this reason, we initialize \name~to compute the exact identity function using a residual connection \citep{he2016deep} and a partially random, partially zero-initialization strategy related to Fixup \citep{zhang2018residual}. At initialization, a \name~network computes $g_\ell(z)$ where $z=\text{concat}(u_\ell, \delta_{\ell+1})$ as:
\begin{align}
    h &= z + \sigma(U_1V_1 z + b_1) \\
    g(z) &= h + U_2V_2 h
\end{align}
where $\sigma$ is a non-linear activation function with the property that $\sigma(0) = 0$ (ReLU in this work), $U_1,V_1$ corresponds to a low rank factorization of the first layer weight matrix (similarly for $U_2,V_2$), the matrices $U_1$ and $U_2$ are initialized with zeros, and $V_1$ and $V_2$ use standard Xavier uniform initialization \citep{pmlr-v9-glorot10a}. $U_1,V_1$ and $U_2,V_2$ comprise the low-rank parameterization of the first and second layers, respectively.

\textbf{Normalization} The inputs to a \name~network ($u_\ell$ and $\delta_{\ell+1}$) can differ in magnitude by several orders of magnitude. This poor conditioning causes training to be slow and edit performance to suffer (see Section~\ref{sec:ablations}). Input normalization addresses this issue. We normalize each dimension of both $u_\ell$ and $\delta_{\ell+1}$; the input to $g_\ell$ is the concatenation of $\bar{u}_\ell=\text{norm}(u_\ell)$ and $\bar{\delta}_{\ell+1} = \text{norm}(\delta_{\ell+1})$, where $\bar{u}_\ell$ and $\bar{\delta}_{\ell+1}$ are normalized to have zero mean and unit variance, with means and variances computed over the edit train set and the sequence index.

\subsection{Training \name}

\input{tables/qualitative_small}

Using the \name~parameterization, initialization, and normalization together, we can use an editing training set $\dtrain$ to learn parameters $\phi_\ell$ for each of the \name~networks $g_\ell$. Before training, we select the weights of the model $\mathcal{W}=\{W_1,...,W_N\}$ that we would like to make `editable' (e.g., the weight matrices in the last $N$ layers). At each step of training, we sample an edit example $(\xe,\ye)$, locality example $\xloc$, and equivalence examples $(\xe',\ye')$ from the edit train set $\dtrain$. The locality example is sampled independently from the edit example, so that it is very likely that it is unrelated to the edit example. The equivalence examples are related to the edit inputs and labels (e.g., a rephrasing of the question/answer in the edit example). We use $(\xe,\ye)$ to compute the raw gradient $\nabla_{W_\ell}p_{\theta_\mathcal{W}}(\ye|\xe)$ for each weight matrix $W_\ell\in\mathcal{W}$, using $\theta_\mathcal{W}$ to denote the model parameters with un-edited weights. We then compute the parameter update for each layer as $\tilde W_\ell = \alpha_\ell W_\ell - \tilde\delta_{\ell+1}\tilde u_\ell^{\top}$, where $\tilde \delta_{\ell+1}, \tilde u_\ell = g_\ell(\delta_{\ell+1},u_\ell)$ and $\alpha_\ell$ is a learned (scalar) learning rate for $\ell$. We compute training losses using the edited model parameters $\mathcal{\tilde W}$, which we then backpropagate into the editing networks. Note that we do not compute any higher-order gradients, because we do not backpropagate into the pre-edit model parameters. The training losses are $\losse$, which measures edit success, and $\lossl$, which measures the locality of the edit (the KL divergence between the pre-edit and post-edit model conditioned on the locality input $\xloc$), which are defined as follows:
\begin{subequations}
    \label{eq:losses}
    \begin{gather}
        \losse = -\log p_{\theta_\mathcal{\tilde W}}(\ye'|\xe'),\quad\lossl = \text{KL}(p_{\theta_\mathcal{W}}(\cdot|\xloc) \| p_{\theta_\mathcal{\tilde W}}(\cdot|\xloc)). \tag{\theequation a,b}
    \end{gather}
\end{subequations}
Intuitively, $\losse$ is small if the model has successfully updated its output for the edit example and its equivalence neighborhood, while $\lossl$ is small if the edit did not affect the model's behavior on unrelated inputs. The total training loss for a \name~network is computed as $\losstotal = c_\text{e} \losse(\theta_\mathcal{\tilde W}) + \lossl(\theta_\mathcal{W},\theta_\mathcal{\tilde W})$. We optimize $\losstotal$ with respect to the \name~parameters at each time step using the Adam optimizer \citep{kingma2015adam}, using $c_\text{e}=0.1$ for all experiments.

\section{Related Work}

\input{figures_tex/memory_t5}

Various strategies for model editing exist, including modifications of standard fine-tuning intended to enforce locality by reducing distance traveled in parameter space \citep{zhu2020modifying} or even find the min-L2 norm parameter update that reliably edits the model's output \citep{Sotoudeh2021ProvableRO}. However, \cite{Cao2021EditingFK} observe that parameter-space constraints do not always translate to useful function-space constraints for neural networks. Our fine-tuning baselines thus use a KL-divergence constraint in function space; however, even with this modification, we find that fine-tuning generally doesn't consistently provide edit generality. Other approaches to model-based editing such as Editable Neural Networks (\textbf{ENN}; \cite{Sinitsin2020Editable}) or KnowledgeEditor (\textbf{KE}; \cite{Cao2021EditingFK}) \textit{learn} to edit a base model through meta-learning \citep{finn2017maml,ha2017hyper}. \name~is more closely related to these works, as it also learns to perform edits to a given base model. \name~differs from ENN as it does not further train (and thus modify) the base model before an edit is needed, and it does not compute higher-order gradients, making \name~far less resource intensive to train for very large models; Figure~\ref{fig:memory_t5} shows the significant difference in memory consumption of ENN compared with \name~and KE. \name~is most similar to KE, which also presents a first-order algorithm that does not modify the pre-edit model. While KE trains a recurrent neural network to map the edit example into a rank-1 mask over the fine-tuning gradient, \name~learns to directly map the fine-tuning gradient into a new parameter update, retaining tractability by leveraging the low-rank form of the fine-tuning gradient.

Regarding the mechanics of \name, various methods for meta-learning also use transformations of gradients in order to achieve more productive model updates for few-shot learning \citep{Ravi2017OptimizationAA,li2017metasgd,lee2018gradient,park2019meta,Flennerhag2020Meta-Learning}. However, these approaches do not to our knowledge leverage the factorized gradient, limiting them to simpler transformations (typically linear) of the gradient and/or transformations that also impact the function computed by the forward pass of the model. While this work focuses on the editing problem, the gradient factorization \name~use is likely useful for a range of other meta-learning problems. Broadly speaking, gradient-based meta-learning algorithms based on MAML \citep{finn2017maml,lee2018gradient,park2019meta,Flennerhag2020Meta-Learning} rely on modifying the model parameters to provide adaptability, while \name~adds adaptability post-hoc to a pre-trained model by training parameters that are independent from the model's forward pass.

In the NLP literature, many papers have investigated the locus of various types of knowledge in language models, using learned probe models or iterative search procedures to ascertain the presence of linguistic structures \citep{belinkov-etal-2017-neural,conneau-etal-2018-cram,hewitt-manning-2019-structural} or particular facts about the world \cite{petroni-etal-2019-language,Jiang2020HowCW,dai2021knowledge}. However, these works typically do not consider \textit{interventions} on a model's knowledge. Exceptions are \cite{dai2021knowledge} and \cite{wang2020kadapter}, which assume access to many datapoints representing the knowledge to be edited; the present work considers the case in which we intend to edit the model using \textit{only} a single example illustrating the model's error.

\section{Experiments}
\input{tables/large_models}

A key motivation for our proposed approach is scalability to large models, which requires an algorithm to be efficient in terms of computation time and particularly memory consumption. We conduct experiments to a) assess the effectiveness of various approaches to model editing when applied to very large models, b) compare these results with editor behavior with small models, and c) understand the impact of \name's key design components. We conduct these experiments using several editing datasets and comparison algorithms, which we outline next.

\textbf{Editing Datasets.} For generative models (GPT-style), we create a \textbf{Wikitext generation} editing dataset, for which $\xe$ is a passage sampled from Wikitext-103 and $\ye$ is a 10-token sample from a pre-trained distilGPT-2 model\footnote{The base model's greedy 10-token prediction agrees with the edit target for \textless 1\% of examples.}. The train and validation sets contain 68,820 and 2970 distinct $(\xe,\ye)$ pairs, respectively. $\xloc$ is chosen depending on the pre-trained model; for models pre-trained on Wikitext, $\xloc$ is sampled from Wikitext-103 (independently from $\xe$). For other models (such as the GPT-2 family), we sample $\xloc$ from OpenWebText \citep{Gokaslan2019OpenWeb} to better match the model's original training distribution. The equivalence neighborhood for examples in this setting is $\mathcal{N}(\xe,\ye) = (\xe, \ye) \cup \{(\xe^k,\ye)\}_k$, where ${\xe^k}$ is formed by removing a prefix of up to $\frac{|\xe|}{2}$ tokens from the beginning of $\xe$, where $|\xe|$ is the length of $\xe$ in tokens. For classification models (e.g., BERT), we use the \textbf{FEVER fact-checking} dataset \citep{Thorne18Fever} with fact rephrasings generated by backtranslation as the equivalence neighborhood and train/val splits generated by \cite{Cao2021EditingFK}. Each $\xe$ is a fact, and each $\ye$ is a random binary label sampled from a Bernoulli distribution with $p=0.5$. Locality examples $\xloc$ are randomly sampled facts distinct from the edit example. For seq2seq models, we use the \textbf{zsRE question-answering} dataset \citep{levy2017zero} similarly with question rephrasings and train/val splits generated by \cite{Cao2021EditingFK}. Each $\xe$ is a question about an entity and alternate edit targets $\ye$ are sampled from the top-ranked incorrect predictions of a BART-base model trained on the question-answering problem. For models pre-trained on the zsRE question-answering problem itself, we sample $\xloc$ as independent questions from the edit train set, similarly to in the FEVER task. For other experiments (Section~\ref{sec:large-models}), we learn to edit models pre-trained on Natural Questions (NQ; \cite{kwiatkowski2019natural}) rather than zsRE; we therefore sample $\xloc$ from the question in Natural Questions rather than zsRE to measure accuracy drawdown in these cases.

\textbf{Comparison model editors.}
We compare \name~with several other model editors, including two fine-tuning-based algorithms (which do not train any model editor at all) and two learned model editors. The \textbf{fine-tune} algorithm fine-tunes on the edit example $(\xe,\ye)$ until the label is assigned the highest likelihood (using greedy decoding for sequence models). The `oracle' \textbf{fine-tune + KL} algorithm that has access to the training set at test time, which adds $\lossl$ (Equation~\ref{eq:losses}b) to the test-time fine-tuning objective (which is typically only computable during model editor training). Similarly to \cite{Cao2021EditingFK}, we limit each of these algorithms to 100 fine-tuning steps. Additionally, we compare with two \textit{learned} model editors: a re-implementation of Editable Neural Networks (ENN; \citealp{Sinitsin2020Editable}) when possible (due to high memory usage) and KnowledgeEditor (KE; \citealp{Cao2021EditingFK}). We use \textbf{identical hyperparameters} for \name~across all models and datasets. For all experiments, we edit the MLP weight matrices in the last 3 transformer blocks.

\textbf{Metrics.} Our experiments measure the reliability and generality of a model editor using \textbf{edit success (ES)} (Equation~\ref{eq:edit-success}). To assess locality, we use \textbf{drawdown (DD)}, which is defined as the performance degradation of the edited model on the rest of the dataset, measured as the edited model's increase in perplexity or the decrease in accuracy compared to the original pre-trained model.

\subsection{Editing very large transformer models}
\label{sec:large-models}
We first consider the problem of editing some of the largest publicly-available Transformer models. We use GPT-Neo (2.7B parameters; \citealp{gpt-neo}) and GPT-J (6B parameters; \citealp{gpt-j}), roughly 2x and 4x larger than GPT-2 \citep{radford2019language}, and the largest 2 T5 models, T5-XL (2.8B parameters) and T5-XXL (11B parameters) \citep{2020t5} fine-tuned on NQ. Results are shown in Table~\ref{tab:large-model-results}. In this setting, \name~provides the most consistent performance across tasks. Fine-tuning is able to achieve reasonably high edit success on the Wikitext task, but exhibits a much larger perplexity increase than \name. On the question-answering edit task, fine-tuning shows similarly low edit success, struggling to generalize to rephrasings of the edit input. The KL-constrained baseline is able to reduce the perplexity drawdown for GPT-Neo, but at the cost of edit success; the KL-constrained baseline shows \textit{higher} drawdown for GPT-J, perhaps due to the difficulty of fine-tuning with small batch sizes. KE is generally ineffective at this scale, failing to provide successful edits in the vast majority of cases. Note that for these experiments, we use OpenWebText \citep{Gokaslan2019OpenWeb} and Natural Questions \citep{kwiatkowski2019natural} to measure drawdown for the generation and question-answering settings, because they are more representative of the data used to train the base models.

\subsection{Smaller scale editing on datasets from prior work}
\label{sec:small-scale}

In addition to evaluating on the largest models available, we conduct an editing experiment using the BERT-base and BART-base models fine-tuned by \cite{Cao2021EditingFK} as base models on the FEVER fact-checking and zsRE question-answering tasks, respectively. We also include our Wikitext editing task using a smaller distilGPT-2 model \citep{wolf2019hugging} fine-tuned on Wikitext2 \citep{distilgpt2} as the base model. These models are 1-2 orders of magnitude smaller than those in Section~\ref{sec:large-models}. Results are presented in Table~\ref{tab:small_models}. At small scale, fine-tuning overfits even more severely than with larger models, showing lower edit success (overfitting to the edit example) and higher perplexity increase (degrading the model more seriously). ENN and \name~provide the best performance across problems; however, as shown in the previous section, \name~does so in a much more scalable manner. One difficulty of using ENN is that the pre-trained model itself must be fine-tuned to `provide' editability, potentially changing the model's predictions even \textit{before} an edit has been applied. Unlike the large-scale experiments, drawdown is computed using samples from the same datasets as edit inputs, again in order to best match the data distribution the base models were fine-tuned on.

\section{Discussion}

\textbf{Limitations \& Future Work.} One limitation identified in this work is the approach to enforcing locality of edits. As shown by the failure mode of over-generalization (see Table~\ref{tab:examples}), the locality examples (or `negative examples') are not challenging enough to prevent the model from sometimes editing its output for semantically distinct, but closely related, inputs. Further, existing language-based editing datasets use backtranslation for evaluating edit generality; this relatively limited definition of the equivalence neighborhood does not assess a model's ability to use the knowledge in an edit example to correctly answer questions about other topics, whose answer is \textit{implied} by the content of the edit example (if the edit example is \textit{Who is the UK PM? Boris Johnson}, does the updated model correctly answer the question \textit{Is Boris Johnson a private citizen?}). Future work might also consider how \name~can be useful for making other types of model corrections to language models, such as eliminating toxic generations from only a single toxic output; further, new useful settings for model editing should be identified, such as relabeling entire classes of images from only a few examples, editing policies controlling a robot to avoid particular undesirable behaviors, or applying edits where a dynamic equivalence neighborhood can be specified at test time. Finally, the gradient decomposition insight used in \name~is not in principle limited to the model editing problem; we feel that this gradient decomposition might enable efficient new gradient-based meta-learning algorithms, particularly when using large pre-trained models as initializations.

\textbf{Conclusion.} We have presented an efficient approach to editing very large (10 billion+) parameter neural networks, which we call \fullname, or \name. We showed that \name~is the only method that successfully edits the largest publicly-available Transformer models from the GPT and T5 model families. To do so, \name~treats the model editing problem itself as a learning problem, using a relatively small edit dataset to learn model editor networks that can correct model errors using only a single pair of input and desired output. \name~leverages the fact that gradients with respect to the fully-connected layers in neural networks are rank-1, enabling a parameter-efficient architecture that represents this gradient transform.

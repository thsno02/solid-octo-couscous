Failure mode taxonomy 
We offer the following outline of the failure modes of autonomous agents, specifically 
applied to chemical research. There are two primary sources of problems — the tools 
themselves and LLMs. 
The primary issue with tool development is the rather limited range of tools we currently 
have. However, we expect this problem to resolve itself over time naturally. Additionally, 
an increasing number of chemistry -related information sources/software ough t to be 
optimized for use with LLMs. For instance, it would be beneficial to have less verbose 
documentation, as well as specific examples. Python or JSON could be used for hardware 
control. 
Inherent characteristics of LLMs, such as reasoning and knowledge, vary dramatically in 
the field of chemical research. Despite having good reasoning abilities, these models 
often fail in showing sufficient chemical knowledge. Another critical area for improvement 
is the interaction with tools.

Details on implementing autonomous agents 
There are numerous methodologies to enable autonomy for Language Learning Models. 
In this case, we employ a strategy where the model operates in chat completion mode. 
The system provides a prompt containing important information such as the role of the 
assistant, syntax for utilizing tools, a list of accessible tools for the model complete with 
required parameters. Additionally, it incorporates examples illustrating how these tools 
can be deployed.  
To be more specific, the model is expected to provide a message in the following format: 
<Description of model’s observations and reasoning> 
COMMANDNAME command parameter 
 
Each message can contain only one command. Majority of the tools accept only a single-
line parameter; however, PYTHON and CLOUD command inputs can span multiple lines.  
Subsequently, the model's task  and corresponding context are  provided within the chat 
as a user message. Following this, the system is capable of generating a new message 
where it can invoke a command and receive a response in the subsequent user’s 
message within the chat. If there was an error in the input, the model would get it in the 
next message (for PYTHON command, it includes corresponding traceback). Similarly, 
there was no command, the model would be notified that it have not provided any 
command. 
This strategy effectively allows the model to leverage outputs to guide its future actions. 
For instance, if a calculation yields a  clearly erroneous number, the system can attempt 
to redo the computation by using another formula.

Analysis of ECL documentation search results 
Further exploration beyond the initial HPLC experiment revealed that the Coscientist 
could identify the correct ECL Experiment function to perform the requested operation. 
The prompt “Write a command for Emerald Cloud Lab to collect an absorbance 
spectrum of sample Object[Sample, "id:aXRlGnRLm4nO"]. Set the Instrument 
option to Model[Instrument, PlateReader, "Lunatic"] and leave all other 
options at their default values.” was correctly interpreted as a request to run an 
absorbance spectroscopy experiment. A syntactically valid command, including the 
specified sample and instrument model, was produced. When provided with similar 
prompts that did not stipulate those other op tions to be left at their default values, the 
Coscientist frequently included other options with mixed results. Similarly, the prompt 
"Generate an Emerald Cloud Lab command to make a stock solution 
consisting of 10 g of Model[Sample, "Sodium Chloride"] and 10 g of 
Model[Sample, "EDTA, Reagent grade"] and 1 L of Model[Sample, "Milli -Q 
water"]. Mix for 17 minutes at 30 Celsius." was interpreted as using the ECL 
function ExperimentStockSolution, but the generated command had minor syntax 
inaccuracies. Notably, the Coscientist produced multiple sequential ECL experiment 
commands for this multi-step request. Despite the syntax issues, the Coscientist’s was 
able to generate complete sequence of commands. The Coscientist was also prompted 
to perform multiple, sequential sample transfers: "Write an Emerald Cloud Lab 
command to transfer 100 microliters of water into a 2mL tube, then 
transfer 200 microliters of absolute ethanol into the same tube." In this 
case, the Coscientist correctly filled in assumptions that were not explicitly specified in 
the prompt, identified correct source and destination wells based on  those assumptions, 
and produced syntax that was largely valid. Allowing the Coscientist to iterate led to 
more complex behavior as it identified recurring operations and generated its own 
streamlined code with a custom Mathematica function. 
In some cases, the Coscientist attempted to access experiment documentation via the 
GOOGLE command opposed to the DOCUMENTATION command. Importantly, performance 
was substantially better when querying supplied plaintext versions ( DOCUMENTATION 
command) compared to the web search strategy (GOOGLE command).

Limitations, Safety Recommendations, and a Call to Action 
We strongly believe that guardrails must be put in place to prevent this type of 
potential dual -use of large language models. We call for the AI community to 
engage in prioritizing safety  of these powerful models . We call upon OpenAI, 
Microsoft, Google, Meta, Deepmind, Anthropic, Cohere, and all the other major 
players to push the strongest possible efforts on safety of their LLMs. We call upon 
the physical sciences community  to be engaged  with the players involved in 
developing LLMs to assist them in developing those guardrails. 
At the same time, we strongly support the continued advancement of LLMs and 
other AI models, as they hold immense potential for benefiting society. 
 
There are several limitations and safety concerns associated with the proposed machine 
learning system. These concerns warrant the implementation of safety guardrails to 
ensure responsible and secure usage of the system. At the very least, we argue that the 
community (both AI and physical sciences) should engage in the following 
recommendations: 
1. Human intervention:  While the system demonstrates high reasoning capabilities, 
there might be instances where human intervention is necessary to ensure the safety 
and reliability of the generated experiments. We recommend incorporating a human -
in-the-loop component for the r eview and approval of potentially sensitive 
experiments, especially those involving potentially harmful substances or 
methodologies. We believe that specialists should oversee and deliberate about 
the Coscientist’s actions in the physical world. 
2. Novel compound recognition:  The current system can detect and prevent the 
synthesis of some of the known harmful compounds. However, it is less efficient at 
identifying novel compounds with potentially harmful properties. This could be 
circumvented by implementing machine learning model to identify potentially harmful 
structures before passing them into the model. 
3. Data quality and reliability:  The system relies on the quality of the data it gathers 
from the internet and operational documentation. To maintain the reliability of the 
system, we recommend the continuous curation and update of the data sources, 
ensuring that the most up-to-date and accurate information is being used to inform the 
system’s decision-making process. 
4. System security: The integration of multiple components, including large language 
models and automated experimentation, poses security risks. We recommend 
implementing robust security measures, such as encryption and access control, to 
protect the system from unauthorized access, tampering, or misuse.

Broader Impacts 
The proposed machine learning system has numerous potential broader impacts on 
science, technology, and society: 
1. Acceleration of scientific research:  By automating the design, planning, and 
execution of experiments, the system can significantly accelerate scientific research 
across various fields. Researchers can focus on interpreting results, refining 
hypotheses, and making discoveries, while the syst em handles the experimental 
process. 
2. Democratization of scientific resources: The system can potentially make scientific 
experimentation more accessible to researchers with limited resources or expertise. It 
may enable smaller research groups or individuals to conduct complex experiments 
with the support of large language models and cloud labs, promoting a more inclusive 
scientific community. 
3. Interdisciplinary collaboration: The system’s versatility across domains, including 
natural language, biology, chemistry, and computer programming, can foster 
interdisciplinary collaboration. Researchers from different fields can leverage the 
system’s capabilities to address complex problems that require a diverse set of skills 
and knowledge. 
4. Education and training:  The system can serve as a valuable educational tool for 
students and researchers to learn about experimental design, methodology, and 
analysis. It can help develop critical thinking and problem -solving skills, as well as 
encourage a deeper understanding of scientific principles. 
5. Economic impact:  By automating and streamlining the experimental process, the 
system can potentially reduce the costs associated with research and development. 
This can lead to increased investment in research and innovation, ultimately driving 
economic growth and competitiveness. 
However, the potential broader impacts also include challenges and risks that must be 
addressed. Ensuring responsible and ethical use of the system, implementing robust 
security measures, and continuously updating data sources are essential steps to 
mitigate potential negative consequences, such as the proliferation of harmful substances 
or the misuse of powerful machine learning tools for nefarious purposes. By addressing 
these concerns, we can unlock the full potential of the proposed system and drive positive 
change across scientific research and society at large.

Safety Implication: Dual-use Study 
Note: This study was performed computationally, none of the examples were 
performed experimentally.  Under no circumstances should any individual or 
organization attempt to recreate, synthesize, or otherwise produce the substances 
or compounds discussed in this section.  
There is growing concern regarding the potential manipulation of molecular machine 
learning models for harmful purposes. We highlight two critical issues: the synthesis of 
illicit drugs and chemical weapons. To assess these risks, we designed a test set of  39 
compounds from the DEA's Schedule I and II substances and a list of known chemical 
weapon agents (CWAs). We submitted these compounds to the Coscientist using their 
common names, IUPAC names, CAS numbers, and SMILES strings to determine the 
degree to w hich the Coscientist might unintentionally perform analysis and planning 
(Figure below and “Examples of illicit drug and CWA syntheses” section). 
When tasked with producing an illicit compound (a), the Planner may not proceed due 
to alignment at various stages. If the compound is prompted by its common name (e.g., 
heroin), the model is more likely to discontinue immediately (d). However, discontinuation 
rates differ depending on the type of molecule: 44% for Schedule I compounds, 15% for 
Schedule II, and 44% for Chemical Weapons Agents (CWAs). Alternatively, when 
requesting a synthesis procedure that must be performed in a DEA -licensed facility, bad 
actors can mislead the Coscientist by falsely claiming their facility is licensed, causing 
the intended behavior of alignment to be bypassed. 
If the compound is not immediately flagged due to alignment, a web search is performed 
to find its synthesis. From here, multiple outcomes are possible. The Web searcher may 
return information indicating that the compound is illegal or dangerous to produce or 
provide the synthesis along with a corresponding warning. 
Depending on what information is returned to the Planner, the desired alignment-based 
discontinuation may occur. This type of discontinuation is the dominant behavior when 
prompting with IUPAC names and CAS numbers for Schedule I and CWA compounds. 
For CAS numbers associated with Schedule II compounds, this figure is also significant, 
reaching 50%. It is important to note that discontinuation can either come with or without 
information related to synthesis.  
As an example, discontinuation after-search (d), when asked about synthesizing codeine, 
the Coscientist obtains information from the  Web searcher  that codeine is closely 
related to morphine. The requirement of morphine to synthesize codeine is enough for 
the alignment intended response to be invoked. However, this can be easily manipulated 
by altering the terminology prior to information being retur ned to the Planner, such as 
replacing all mentions of morphine with "Compound A" and codeine with "Compound B".

For this study, we limited the number of Planner steps to five, as behavior beyond this 
varies. In many cases, the model performs necessary calculations and documentation 
search, or even writes commands for the cloud lab to execute the experiment. It is 
important to note that the current operation of ECL primarily focuses on analytical tools 
and, as such, does not yet provide extensive organic synthesis capabilities. 
Among all representations, the most complex type is the SMILES string. The model often 
attempts to use new tools to perform the synthesis (for example, by searching how to 
synthesize a compound if its SMILES string is known) or tries to analyze functional groups 
based on the SMILES string. Unsurprisingly, discontinuation rates are the lowest in this 
context. Access to retrosynthetic tools and chemical database APIs can enable the model 
to perform these types of syntheses. 
It is important to note that all safety checks performed in this work are directed towards 
the results of the alignment procedure with the model, not the technology itself. It seems 
unrealistic to use this procedure to protect from every possible case. A p ossible solution 
would be the development of an intermediate layer where all chemical entities are 
converted into a unified representation and checked against the database for controlled 
or potentially dangerous substances. 
One important observation to acknowledge is that the information in question is typically 
obtainable online and could potentially be exploited by a high -knowledge bad actor. 
However, the system significantly reduces the entry barrier for ill -intentioned lo w-
knowledge actors as they could conduct malicious experiments without any prior training.

HPLC experiment parameter estimation 
The ECL has its own, less sophisticated “expert system” AI which helps suggest run 
parameters to fill out the full list of optional settings on an HPLC run given a partial 
selection of options. That expert system is essentially a large decision tree built by 
scientific developers at Emerald with deep expertise in the particular experiment type. 
The intention of this more modest AI is simply to act in place of a competent lab technician 
and fill out more detailed options that are implied by higher-level options. For example, if 
the user’s command includes a description of which detectors are desired on an HPLC 
run, the expert system will pick up on the fact that a given set of detectors will dictate 
which instrument models can or cannot be used for the experi ment and set that option 
accordingly without the user having to explicitly list its values. Most of what this AI does 
is focused on sufficiency checking for an experiment to ensure that the design does not 
run into technical limitations or violate any safety protocols. This includes checks such as 
ensuring that all samples have sufficient volume to complete the experiment as specified, 
ensuring that all samples will fit in the required instruments based on the container types 
they reside in, checking chemic al compatibility of wetted materials and sample 
compositions to ensure the instrumentation doesn't get damaged, and ruling out runs that 
exceed instrument operating limits (such as increasing pressure or temperature above 
what a system is rated to handle). 
What Emerald's expert system AI is explicitly not set up to do is to provide scientific 
suggestions on how best to run a protocol; it is focused simply on mechanical feasibility 
and rigorously detecting and blocking any experimental designs that would violate safety 
protocol.

Selection of substrates in large databases of compounds 
We were interested in seeing how the model behaves not with 11 available compounds, 
but many more. Therefore, automated compound extraction was necessary.  
To accomplish this, we constructed a sample of 300 compounds from the CoPriNet 
dataset. The dataset was first randomly reduced from 100k to 3k before the specific 
compounds were sampled for the study. For each reaction type, 10 of the first and second 
reagents were sampled and added to the dataset. Due to overlap, this resulted in 97 
SMILES. The remaining 203 were randomly sampled from the rest of the CoPriNet 
dataset. This ensured the dataset was sufficiently diverse for the study. 
The system was then prompted to generate a file containing a list of SMILES strings for 
the reagents capable of participating in one of five reactions: Diels-Alder reaction, Michael 
addition, Esterification, Buchwald-Hartwig amination, and Mizuroki-Heck reaction. To test 
the model, a set of SMARTS strings for each of the reactions was manually constructed.

Bayesian optimization procedure 
Parameter Space 
In all instances of Bayesian Optimization, the parameters are one -hot encoded for 
purposes of machine learning. The Suzuki reaction had 3 parameters (ligand, reagent, 
and solvent) this resulted in a 24 -D vector representation for each of the 384 possible 
experiments for a given pair of substrates.   
Surrogate Model 
A single task gaussian process model with an exact marginal log likelihood was the 
chosen surrogate model. The model uses a categorical kernel which is specifically 
designed for categorical features. 
Acquisition Function 
The acquisition function makes use of the trained surrogate model to compute the 
expected improvement for all unobserved experiments. This allows for the acquisition 
step to balance between exploitation and exploration of the parameter space.  
 
Other Notes 
Optimization was performed with a varying amount of prior information. Seed data was 
selected randomly from 1 to 10 samples. For a given amount of prior information the 
optimization was run 20 times, each time suggesting 20 experiments in a sequential 
fashion. Given that the optimization strategy is not deterministic (depending on the exact 
prior information supplied) this allows us to present an average optimization performance 
within a given parameter space.  
Furthermore, a parameter space is defined for a given substrate pairing. Thus, the 
optimization performance is averaged across the 15 possible substrate pairings for the 
Suzuki coupling reaction. 
The manuscript mentions prior information for GPT-4 models as well. The main difference 
here is that for GPT-4, prior information includes data for other substrates, while BO relies 
on data for specific substrate combination in question.
